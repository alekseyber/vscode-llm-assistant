## Назначение

Локальный лексический индекс кодовой базы поверх SQLite FTS5: улучшает выдачу существующего
инструмента `search_files` (ранжирование BM25 с весом пути), не меняя его контракт. Индекс —
внутренняя деталь расширения: его отсутствие или порча не ломают поиск, а откатывают к текущему
ripgrep-поведению. Это **не** RAG: эмбеддингов и векторного поиска здесь нет.

## Интерфейс

### `normalizeText(text: string): string`

| Вход | Тип | Описание |
|------|-----|----------|
| text | string | Исходный текст (код, путь, запрос) |

| Выход | Тип | Описание |
|-------|-----|----------|
| — | string | Токены через пробел: нижний регистр, `ё`→`е`, идентификаторы разбиты на части, русские окончания отсечены |

### `buildFtsQuery(text: string, maxTokens = 12): string`

Собирает безопасный запрос FTS5 из пользовательского текста.

| Вход | Тип | Описание |
|------|-----|----------|
| text | string | Сырой запрос пользователя («где считается стоимость (run)») |
| maxTokens | number | Потолок токенов (по умолчанию 12) |

| Выход | Тип | Описание |
|-------|-----|----------|
| — | string | `tok1 tok2 …` (AND по токенам) или `"tok"` для одного токена; пустая строка, если токенов нет |

Спецсимволы FTS5 (`(`, `)`, `-`, `"`, `OR`, `NOT`, `*`, `:`) в запрос не попадают: они либо
выбрасываются токенизатором, либо экранируются кавычками.

### `new SearchIndexStore(options)`

| Параметр | Тип | Описание |
|----------|-----|----------|
| options.indexPath | string | Абсолютный путь к файлу индекса в `globalStorage` |
| options.onDebug | (msg: string) => void | Канал «LLM Assistant» (необязательно) |

### `store.init(): Promise<boolean>`

Загружает БД (`fs.readFile` → `new SQL.Database(bytes)`), создаёт схему при первом запуске.
Возвращает `false`, если WASM недоступен или файл несовместим — вызывающий код деградирует к ripgrep.

### `store.upsertFile(entry): void` / `store.removeFile(path): void`

| Вход | Тип | Описание |
|------|-----|----------|
| entry.path | string | Путь относительно корня рабочего пространства |
| entry.body | string | Исходный текст (для сниппетов и нормализации) |
| entry.size, entry.mtime | number | Признаки для сверки |

`upsertFile` перезаписывает строку: сначала `DELETE` из `files` и `fts` по пути, затем `INSERT`.

### `store.search(query, limit): SearchHit[]`

| Выход | Тип | Описание |
|-------|-----|----------|
| path | string | Путь файла |
| rank | number | BM25 (меньше — лучше) |
| snippet | string | Первые 200 знаков совпавшего места |

### `store.flush(): Promise<void>` / `store.export(): Uint8Array`

`flush` пишет БД на диск атомарно (temp + rename). Точки вызова: после пачки индексации (200 файлов),
по debounce 2 с, в `deactivate()`.

### `store.listIndexed(): Array<{ path; size; mtime }>`

Снимок проиндексированного — для сверки при старте (S2).

### `store.stats(): { files: number; skipped: number; bytes: number }`

## Контракты

| Ситуация | Поведение |
|----------|-----------|
| WASM не загрузился | `init()` → `false`, одна debug-строка; поиск идёт ripgrep-путём |
| Файл индекса повреждён | Удаляется, `init()` возвращает `false`; пересборка в фоне, поиск пока ripgrep |
| Схема старше текущей версии | Файл индекса удаляется, индекс строится заново (никаких частичных миграций) |
| Спецсимволы FTS5 в запросе | Выбрасываются токенизатором; запрос не падает и не меняет логику |
| Запрос из одних спецсимволов | Пустой FTS-запрос → вызывающий код уходит в ripgrep |
| Файл больше 512 КБ, бинарный (NUL в первых 4 КБ), UTF-16 без BOM | Не индексируется, попадает в `skipped` |
| Файл в `node_modules`, `dist`, `out`, `.git`, `*.min.js`, lock-файл | Не индексируется |
| `.gitignore` исключает файл | Не индексируется |
| Больше 20 000 файлов / индекс больше 15 МБ | Индексируются самые свежие по `mtime`, остаток — в `skipped` + debug-строка |
| `mtime`+`size` совпали, но файл изменён в последние 5 с | Дополнительная сверка `crc32` первых 4 КБ |
| Индекс перестраивается | Поиск продолжает работать ripgrep-путём, без тостов |

## Детали реализации

**Движок.** `@sqlite.org/sqlite-wasm` (WASM, без нативных модулей в VSIX). `sql.js` отвергнут:
FTS5 в нём нет (`no such module: fts5`, проверено прогоном).

**Схема.**

```
files(path TEXT PRIMARY KEY, ext TEXT, size INTEGER, mtime INTEGER, crc INTEGER)
fts(path UNINDEXED, path_tokens, body_norm)   -- fts5, внешнего контента нет
```

`path_tokens` — индексируемая колонка с нормализованным путём: без неё `bm25()` не может учесть путь.
Веса: `path_tokens` 4.0, `body_norm` 1.0.

**Нормализация.** Нижний регистр, `ё`→`е`, пунктуация → пробел; `calculateCost` →
`calculate cost calculatecost`; `PROMPT_EVAL_COUNT` → `prompt eval count prompt_eval_count`;
русские окончания отсекаются простым списком (без словаря); английские словарные формы не стеммим.

**Персистентность.** sqlite-wasm не открывает файл хоста напрямую: БД в памяти, на диск — через
`db.export()` (атомарно: temp + rename). Путь: `<globalStorage>/index/<sha1(корень)>.sqlite`.

**Чанкинг.** Extension Host однопоточный: индексация пачками по 200 файлов с `await` между пачками,
чтобы самая длинная синхронная задача не превышала 50 мс.

## Тесты (searchIndex.test.ts)

- IDX-1: нормализация — регистр, `ё`, camelCase/snake_case, русские окончания
- IDX-2: создание схемы на пустом индексе; повторная инициализация не ломает данные
- IDX-3: схема старой версии → индекс пересобран с нуля
- IDX-10: запрос со спецсимволами `(run)`, `-`, `OR` не падает и находит ожидаемое
- IDX-11: `flush` → новый экземпляр → те же результаты поиска
- IDX-12: WASM недоступен/индекс битый → `init()` false, поиск не падает

## Связи

- **Использует:** `Logger` (debug-канал), `vscode.workspace` (обход файлов), `@sqlite.org/sqlite-wasm`
- **Используется:** `ToolDefinitions.search_files` (S3), `extension.activate` (S2)
- **Не меняет:** контракт `search_files` — параметры и формат ответа остаются прежними
  (зафиксировано в `specs/ChatAgentTools.md`)
