## Назначение

Разбор и применение правил `.gitignore` без зависимости от VS Code API. Вынесено из
`ToolDefinitions`, потому что то же поведение нужно индексатору (P8), а он обязан работать
в обычном Node (стенд, скрипты замеров, тесты без Extension Host).

## Интерфейс

### `parseGitignore(text: string): string[]`

| Вход | Тип | Описание |
|------|-----|----------|
| text | string | Содержимое `.gitignore` |

| Выход | Тип | Описание |
|-------|-----|----------|
| — | string[] | Правила без комментариев, отрицаний (`!`), ведущих и хвостовых слэшей |

### `isIgnored(relativePath: string, rules: readonly string[]): boolean`

| Вход | Тип | Описание |
|------|-----|----------|
| relativePath | string | Путь относительно корня (любой разделитель) |
| rules | string[] | Результат `parseGitignore` |

## Контракты

| Ситуация | Поведение |
|----------|-----------|
| Правило с `*` без слэша (`*.log`) | Действует на любом уровне вложенности, как в git |
| Правило со слэшем (`/dist`, `build/out`) | Привязано к началу пути |
| Правило-каталог (`node_modules`) | Совпадает сам каталог и всё внутри |
| Отрицание (`!important.txt`) | Игнорируется: индексатор и поиск такое не поддерживают |
| Пустой список правил | Ничего не игнорируется |

## Детали реализации

Шаблоны с `*` компилируются в регулярное выражение: `**` → любой путь, `*` → сегмент без слэша;
для правила без слэша добавляется префикс `(^|.*/)`, иначе корневое `*.log` не ловило
`src/deep/file.log` (дефект, найденный ревью S2).
