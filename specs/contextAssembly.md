# contextAssembly

**Версия:** 0.1.0
**Файл:** `src/shared/contextAssembly.ts`

## Назначение

Сборка запроса к модели — системный промпт, правила проекта и история с прикреплённым контекстом кода.
Вынесена из `ConversationManager` в чистую функцию, чтобы **стенд evals собирал контекст тем же кодом, что и
панель чата**. До этого стенд вырезал фрагмент своими руками и проверял модель, а не продукт: ошибка в
сборке контекста не могла уронить ни один прогон.

## Интерфейс

| Функция | Вход | Выход |
|---------|------|-------|
| `assembleRequestMessages(input)` | `{ systemPrompt, agentsMd?, messages, maxTokens }` | `{ messages, trimmed, systemPrompt }` |
| `systemPromptWithAgents(systemPrompt, agentsMd?)` | промпт, правила проекта | промпт с разделом «Правила проекта» |
| `formatCodeContext(context?)` | `{ filePath, content, … }` | блок `--- Файл: … ---` с ограждением |
| `estimateTokens(text)` | строка | `ceil(length / 4)` |

## Контракты

- Системное сообщение всегда первое; `messages[0].content` равен `systemPromptWithAgents(...)`.
- **Контекст кода учитывается в бюджете наравне с текстом сообщения.** Иначе большой прикреплённый файл
  молча вытесняет историю: пользователь видит «полный контекст», а модель получает обрезанный диалог.
- **Хотя бы одно последнее сообщение остаётся всегда**, даже если оно не влезает целиком: запрос без вопроса
  хуже, чем обрезанный вопрос.
- Контекст приклеивается к сообщению пользователя (`msg.content + блок`), а не отдельным сообщением —
  модель должна видеть вопрос и файл вместе.
- В `trimmed` контекст файлов не попадает: суммаризатору нужен смысл диалога, а не код.
- `trimmed` идёт от старых сообщений к новым.
- Формат блока (`--- Файл: <путь> ---` и тройное ограждение) — часть контракта: по нему модель отличает
  вопрос от файла, а тесты и стенд сверяют одинаковый вид.

## Связи

`ConversationManager.getMessagesForRequest` (продукт, ветка без журнала), `SessionLog.deriveMessagesWithTrimmed`
(путь с журналом сессий — тоже делегирует сюда, второй реализации правила обрезки нет),
`scripts/evals/run.mjs` (стенд; грузит собранный `out/src/shared/contextAssembly.js`),
`contextWindow.resolveContextTokens` (источник `maxTokens`).

## AC (таблица: ID → критерий → статус)

| ID | Критерий | Статус |
|----|----------|--------|
| CA-1 | Контекст размечен заголовком файла и ограждением; без контекста блок пуст | ✅ |
| CA-2 | Контекст приклеен к сообщению пользователя, вопрос впереди | ✅ |
| CA-3 | Контекст учитывается в бюджете: бюджет 20 токенов → старые сообщения обрезаны | ✅ |
| CA-4 | Последнее сообщение остаётся при любом бюджете | ✅ |
| CA-5 | AGENTS.md дописывается разделом «Правила проекта», пустой — не добавляет | ✅ |
| CA-6 | `trimmed` от старых к новым, без контекста файлов | ✅ |
| CA-7 | Оценка токенов одна на всех (4 символа на токен) | ✅ |
