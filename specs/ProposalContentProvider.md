# ProposalContentProvider

## Назначение

Виртуальные документы для показа предлагаемой правки в родном diff-редакторе VS Code.
Декорации в исходном файле показывают только места, куда придёт правка, но не сам новый код:
при частичном выделении подсвеченные строки визуально совпадают с уже существующим текстом,
и пользователь видит «плюсы» без содержания. Поэтому предложение открывается через `vscode.diff`:
слева файл как есть, справа результат замены.

## Интерфейс

| Метод | Назначение |
|---|---|
| `register(): Disposable` | регистрирует провайдер для схемы `llma-proposal` |
| `set(uri: Uri, text: string): void` | кладёт текст и уведомляет подписчиков `onDidChange` |
| `delete(uri: Uri): void` | удаляет текст (после accept/reject) |
| `provideTextDocumentContent(uri: Uri): string` | отдаёт текст по URI; для неизвестного — пустая строка |
| `onDidChange: Event<Uri>` | событие обновления виртуального документа |

## Контракты

- Файлы на диск не пишутся: содержимое живёт в памяти процесса расширения.
- Схема URI — `llma-proposal` (константа `PROPOSAL_SCHEME`).
- Язык подсветки VS Code определяет по расширению в пути URI, поэтому расширение исходного файла сохраняется.
- Регистрация ленивая: провайдер создаётся при первом предложении правки.

## Связи

- Вызывается из `EditController.showProposalDiff`.
- Пару текстов готовит `proposalPreview.buildProposalPreview`.
- Тесты: `EDH-6` (команда `vscode.diff` получает «до» и «после»), `EDH-7` (настройка `edit.showProposalDiff=false` отключает предпросмотр).
