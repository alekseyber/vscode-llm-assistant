## Назначение

Сводка по истории запусков: сколько стоит работа по типам задач и где агент падает. Нужна, чтобы настройка бюджета и маршрутизации моделей (P9) опиралась на цифры, а не на интуицию. Модуль чистый — считает по массиву `RunEntry`, без VS Code.

## Интерфейс

### `computeRunStats(runs, sinceMs?) → RunStats`

Считает: количество запусков, суммарную и среднюю стоимость, число успешных / с ошибкой / отменённых / упёршихся в лимит, долю ошибок, а также группы `byMode` и `byModel` (у каждой — count, cost, costAvg, failRate, durationAvg; сортировка по стоимости убыв.).

`sinceMs` — нижняя граница `timestamp`: если задана, учитываются только более новые запуски.

### `filterRuns(runs, sinceMs?) → RunEntry[]`

Отдельный фильтр по периоду — используется и сводкой, и вызывающим кодом.

### `formatStatsLine(stats) → string`

Готовая строка для вкладки «История»: `N запусков · $X всего · $Y в среднем · ошибок Z%`. Для пустой истории — «Запусков нет».

## Контракты

| Ситуация | Поведение |
|----------|-----------|
| Пустая история | нули, `byMode`/`byModel` пустые, строка «Запусков нет» (RS-1) |
| Есть успешные и ошибочные | сумма, средняя стоимость и доля ошибок считаются (RS-2) |
| Разные режимы | группировка по `mode`, доля незавершённых успешно (`error`, `cancelled`, `limit_exceeded`) (RS-3) |
| Разные модели | группировка по `model`, сортировка по стоимости (RS-4) |
| Период | запуски старше `sinceMs` не учитываются (RS-4) |
| Формат строки | запуски, суммы $, процент ошибок (RS-5) |

## Границы

- стоимость берётся из записи `RunEntry.cost`, то есть из того, что посчитал провайдер (`calculateCost`); локальные модели дают `0`;
- `failRate` в группах считает отмены и лимит как неуспех, а `errorRate` в общей сводке — только `status: 'error'`. Это разное по смыслу: «не довёл до конца» против «упал».
