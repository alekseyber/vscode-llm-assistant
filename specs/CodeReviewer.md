## Назначение

Standalone AI-ревью кода — отдельный ReviewerAgent (ReAct через AgentWorker с инструментами `read_file`/`search_files`/`list_files`) ревьюит файл или выделенный код и выдаёт структурированный markdown-отчёт (стиль / безопасность / корректность / оптимизация). Выделен из Plan Mode `reflect()` — там ревьюер завязан на проверку AC плана, здесь — на ревью произвольного кода.

## Интерфейс

```typescript
interface CodeReviewResult {
  report: string;       // markdown-отчёт
  iterations: number;   // сколько итераций потратил агент
  cost: number;         // стоимость вызова
}

class CodeReviewer {
  // Ревью файла по абсолютному пути (агент читает файл инструментом read_file)
  reviewFile(filePath: string, provider: any, model: string, signal?: AbortSignal): Promise<CodeReviewResult>;

  // Ревью сырого кода (выделение/дифф) — код передаётся в задачу напрямую
  reviewCode(code: string, language: string, filePath: string, provider: any, model: string, signal?: AbortSignal): Promise<CodeReviewResult>;
}
```

## Контракты

| Ситуация | Поведение |
|----------|-----------|
| `reviewFile` вызван с существующим путём | Агент читает файл через `read_file`, ревьюит, возвращает отчёт |
| `reviewFile` вызван с несуществующим путём | Агент пробует читать → получает ошибку → возвращает отчёт с пометкой «файл не найден» |
| `reviewCode` с кодом | Код передаётся в задачу (`task`), агент ревьюит без чтения с диска |
| Пустой код/пустой путь | Ранний возврат ошибки «нет кода для ревью» (без вызова LLM) |
| Отмена (`signal.aborted`) | Агент прерывается, возвращает `{ report: 'Отменено', ... }` |
| Провайдер без `createWithTools` | Ошибка «провайдер не поддерживает агентный режим» |

## Детали реализации

- Роль агента: `name: 'code-reviewer'`, `allowedTools: ['read_file', 'search_files', 'list_files']`, `model` — как в `reflect()`.
- `AgentWorker` с `maxIterations: 8`, `skipGlobalAllowList: true` (ревьюеру нужен read_file независимо от пользовательского allow-list).
- `CODE_REVIEW_SYSTEM_PROMPT` — директивный промпт ревьюера (секции: стиль, безопасность, корректность, оптимизация; формат — список по приоритету критично/важно/мелко, markdown, по-русски). Адаптирован из `/review` слэш-команды, но для агентного режима (реально читает файлы, а не полагается на прикреплённый контекст).

## Промпты

`CODE_REVIEW_SYSTEM_PROMPT` (директивный, для ReAct-агента):

```
Ты — код-ревьюер. Твоя задача — найти проблемы в коде.
1. Прочитай указанный файл через read_file (путь будет в задаче).
2. При необходимости найди связанные файлы через search_files/list_files.
3. Составь отчёт по секциям:
   - Стиль: именование, форматирование, читаемость
   - Безопасность: уязвимости, инъекции, утечки, гонки
   - Корректность: ошибки, граничные случаи, обработка исключений
   - Оптимизация: лишние вычисления, сложность, узкие места
4. Формат: список замечаний по приоритету (🔴 критично / 🟠 важно / 🟡 мелко), markdown, по-русски.
НЕ ИСПРАВЛЯЙ код — только докладывай.
```

## AC

| ID | Критерий | Статус |
|----|----------|--------|
| CR-1 | `reviewFile` запускает ReviewerAgent (ReAct, maxIterations=8, skipGlobalAllowList) | ✅ |
| CR-2 | `reviewCode` передаёт код в задачу и ревьюит без чтения с диска | ✅ |
| CR-3 | Отчёт содержит секции стиль/безопасность/корректность/оптимизация | ✅ (промпт диктует секции) |
| CR-4 | Пустой код/путь → ранний возврат ошибки без вызова LLM | ✅ |
| CR-5 | Команда «LLM Assistant: Review File» ревьюит активный файл и показывает отчёт | ✅ |
| CR-6 | Отмена по `signal` не зависает | ✅ (signal проброшен в AgentWorker) |

## Связи

- **Использует:** `AgentWorker` (ReAct), `ChatAgentTools` (read_file/search_files/list_files), `calculateCost`.
- **Используется:** `registerCommands.ts` (команда «Review File»), `ChatViewProvider` (показ отчёта).
- **Связан:** `PlanModeManager.reflect()` — общий паттерн ReviewerAgent (промпт разный: там AC плана, здесь код).

## Тесты

- `codeReviewer.test.ts` — мок AgentWorker/LLM: reviewFile передаёт путь в задачу, reviewCode передаёт код, пустой вход → ранняя ошибка, отмена.
- E2E `review.e2e.ts` — команда ревью с мок-провайдером, отчёт попадает в сессию.
