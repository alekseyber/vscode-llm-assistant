## Назначение

Наполняет локальный индекс (`SearchIndex`) из рабочего пространства: обход и фильтры, детект
не-текста, пачки с отдачей управления хосту, инкрементальные обновления и сверка при старте.
Файловая система передаётся снаружи адаптером, поэтому логика не зависит от VS Code API
и проверяется на настоящем диске.

## Интерфейс

### `new SearchIndexer(store, adapter, options)`

| Параметр | Тип | Описание |
|----------|-----|----------|
| store | SearchIndexStore | Хранилище индекса (S1) |
| adapter | IndexFsAdapter | `listFiles()`, `readFile(relPath)`, `readGitignore?()` |
| options.maxFiles | number | Потолок файлов (по умолчанию 20 000) |
| options.batchSize | number | Размер пачки (по умолчанию 200) |
| options.onDebug | (msg: string) => void | Канал «LLM Assistant» |

### `fullBuild(): Promise<IndexStats>`

Обход всех файлов, применение фильтров, запись пачками с `await` между пачками, flush после
каждой пачки, удаление из индекса того, чего больше нет на диске.

### `reconcile(): Promise<IndexStats>`

Сверка при старте: индексирует новые и изменившиеся файлы (по `size`+`mtime`), удаляет исчезнувшие.
Полная перестройка не запускается, если изменилось немного.

### `updateFile(file)` / `removeFile(relPath)`

Инкремент одного файла. Файл, который перестал проходить фильтры (например, попал в `.gitignore`
или вырос больше лимита), удаляется из индекса — иначе он остаётся в выдаче «навсегда».

### Чистые функции

| Функция | Назначение |
|---------|-----------|
| `skipReason(file, rules?, maxBytes?)` | Причина пропуска: `каталог`, `lock/минифицированный`, `расширение`, `размер`, `.gitignore`; `null` — индексируем |
| `decodeIndexableText(bytes)` | Текст или `null`: NUL без BOM, битый UTF-8, UTF-16 без BOM → не текст; UTF-16 с BOM декодируется |
| `parseGitignore(text)` | Правила `.gitignore` (переиспользование из `ToolDefinitions`) |

## Контракты

| Ситуация | Поведение |
|----------|-----------|
| Файл в `node_modules`, `dist`, `out`, `.git`, `build`, `coverage`, `vendor` | Не индексируется (`каталог`) |
| Lock-файл, `*.min.js`, `*.map` | Не индексируется (`lock/минифицированный`) |
| Расширение вне белого списка | Не индексируется (`расширение`) |
| Файл больше 512 КБ | Не индексируется (`размер`) |
| Путь под правилом `.gitignore` | Не индексируется (`.gitignore`) |
| NUL-байт без BOM, битый UTF-8, UTF-16 без BOM | Не индексируется (`не текст`), сборка продолжается |
| Ошибка чтения одного файла | Пропуск, причина `ошибка чтения`, сборка продолжается |
| Файлов больше `maxFiles` | Индексируются самые свежие по `mtime`, остаток — в `reasons['потолок файлов']`, debug-строка |
| Файл удалён с диска | Удаляется из индекса при сверке или по `removeFile` |
| Файл перестал проходить фильтры | Удаляется из индекса |
| Пачка обработана | `flush` на диск + отдача управления хосту (`setTimeout 0`) |

## Детали реализации

**Фильтры.** Белый список текстовых расширений (код, разметка, конфиги), чёрный список каталогов,
lock-файлы и минифицированные бандлы; `.gitignore` читается из корня и применяется к
относительным путям.

**Детект не-текста.** Белого списка мало: UTF-16, бинарный `.txt` и минифицированный JSON
проходят по расширению. Проверка: NUL в первых 4 КБ без BOM → не текст; строгий UTF-8 (`fatal`)
→ при ошибке пробуем UTF-16LE/BE по BOM, иначе не текст.

**Пачки.** Extension Host однопоточный, поэтому 200 файлов → `flush` → `setTimeout(0)`.
Это даёт хосту обработать события между пачками.

**Сверка.** Сравнение `size` и `mtime` из таблицы `files` с диском; файлы с совпадением не
перечитываются. Для файлов, изменённых в последние 5 с (грубое разрешение ФС), S3 добавит
`crc32` первых 4 КБ — в S2 признаков два.

## Тесты (searchIndexer.test.ts)

- IDX-4: полная сборка обходит каталоги, применяет фильтры и `.gitignore`
- IDX-5: инкремент — изменение и удаление одного файла
- IDX-6: пачки пишут индекс на диск по ходу сборки; перезапуск видит данные
- IDX-13: бинарные и UTF-16 без BOM не индексируются, сборка не падает
- IDX-14: два корня индексируются независимо (основа multi-root)
- IDX-15: сверка при старте обновляет изменённое и убирает исчезнувшее

## Связи

- **Использует:** `SearchIndex` (хранилище и нормализация), `ToolAllowList`-независимые правила
  `.gitignore` из `ToolDefinitions`
- **Используется:** `extension.activate` (S3 — фоновая сборка и watcher)
- **Не меняет:** контракт `search_files` — индекс подключается к инструменту в S3
