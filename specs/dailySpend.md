# dailySpend

**Версия:** 0.2.0
**Файл:** `src/shared/dailySpend.ts`

## Назначение

Дневной счётчик расхода опирается на `Memento` (read-modify-write). Кэш в памяти окна
затирал расход, записанный другим окном VS Code: два окна видели разные суммы и оба могли
пройти мимо дневного лимита. Функция задаёт одно правило слияния.

## Интерфейс

| Функция | Вход | Выход |
|---------|------|-------|
| `mergeDailySpend(stored, cached, usdMicro, date)` | записанное состояние, кэш окна, расход в микро-$, локальная дата | `DailySpendState` |
| `toMicro(usd)` / `fromMicro(usdMicro)` | доллары ↔ микро-доллары | целое / число |

## Контракты

- Деньги хранятся целыми **микро-долларами** (`1_000_000` = $1): float копил ошибку (`1.1 + 0.1 ≠ 1.2`).
- Состояние: `{ date, usdMicro, rev }`. `rev` растёт при каждой записи и при ручном сбросе.
- Если `rev` в `globalState` больше `rev` кэша — источник записанное (иначе сброс отменялся бы старым кэшем другого окна).
- При равных ревизиях база = `max(stored.usdMicro, cached.usdMicro)`; записи за другую дату игнорируются.
- Приращение не конечное или `≤ 0` — 0 (счётчик не уменьшается).
- Нечисловые значения в `stored`/`cached` трактуются как 0 (`NaN` имеет тип `number` и иначе отравил бы счётчик).
- Возвращается новое состояние; входные объекты не мутируются.
- `Memento` не даёт атомарности: одновременная запись из двух окон может потерять одну порцию (миллисекундное окно). Надёжный источник истины — счёт у провайдера, счётчик охраняет лимит и не претендует на бухгалтерию.
- Старая запись `{date, usd}` (до 0.23.9) читается и переводится в микро-доллары.

## Связи

Вызывается `ChatViewProvider.addDailySpend`; лимит проверяется в `checkBudget` (P9.1, дневной cap).
