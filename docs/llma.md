# `.llma/` — справочник по папке проекта

Единая точка правды: что плагин читает из `.llma/`, в каком порядке, с какими лимитами и что пишет сам. Источник — код (`src/shared/RoleAgentsMdLoader.ts`, `src/shared/AgentsMdLoader.ts`, `src/modes/chat/PlanModeManager.ts`, `src/modes/chat/ChatViewProvider.ts`).

## Дерево

```
проект/
├── AGENTS.md                 ← правила проекта (стандарт, читают и другие агенты)
└── .llma/
    ├── main.md               ← правила главного агента (чат + 🤖 Агент)
    ├── agents/
    │   ├── architect.md      ← роль для @orchestrate и делегирования
    │   ├── coder.md
    │   └── reviewer.md
    ├── skills/
    │   └── my-skill.md       ← кастомный скил, вызов: /my-skill или /skill my-skill
    └── plans/
        └── plan_2026-11-08_4c4b57f0.md   ← пишет План-режим
```

Все файлы опциональны. Если папки или файла нет — используются дефолтные промпты плагина, ошибок не будет.

## Что куда инжектится

| Источник | Куда попадает | Когда |
|----------|---------------|-------|
| `AGENTS.md` (корень проекта) | system prompt чата и агента, блок «Правила проекта (AGENTS.md)» | если `llmAssistant.agentsMd.enabled = true` (по умолчанию) и файл есть |
| `.llma/main.md` | system prompt главного агента чата | всегда, если файл есть |
| `.llma/agents/{role}.md` | system prompt воркера с этим именем роли (`@orchestrate`, делегирование, Review) | при создании воркера |
| `.llma/skills/*.md` | каталог «имя + описание» в промпт агента; сам файл — только когда агент его прочитает | в режиме 🤖 Агент |
| `.llma/plans/*.md` | читает План-режим и ревьюер плана | План-режим |

Порядок для ролей: `.llma/agents/{role}.md` → `.llma/main.md` → `null` (дефолтный промпт роли). То есть `main.md` подхватывается только если файла роли нет.

## `main.md`, `AGENTS.md`, `CLAUDE.md` — что писать куда

- `AGENTS.md` — правила для любого агента в этом репозитории (конвенции кода, язык комментариев, запреты). Его читают и другие инструменты (Codex, Cursor, Cline), поэтому держим там общее.
- `.llma/main.md` — то, что касается именно этого плагина: как отвечать, куда складывать артефакты, чего не делать.
- `CLAUDE.md` — если проект настроен под Claude Code; читается третьим, чтобы правила не пропадали при переезде.

Все найденные файлы инжектятся одновременно, в порядке `AGENTS.md` → `.llma/main.md` → `CLAUDE.md`,
с подписью источника (`### Источник: …`). Общий лимит — `agentsMd.maxChars` (12 000 знаков):
лишнее отрезается по границе строки и помечается в промпте. Дублировать правила не нужно —
конфликт останется на усмотрение модели, поэтому лучше держать один источник правды.

## Совместимость с `.claude/` (Claude Code)

| Что | Откуда читается | Приоритет |
|-----|-----------------|-----------|
| Правила проекта | `AGENTS.md`, `.llma/main.md`, `CLAUDE.md` | в указанном порядке, все три склеиваются |
| Скилы | `.llma/skills/<имя>.md`, `.claude/skills/<имя>/SKILL.md` | `.llma` выигрывает при совпадении имён |
| Роли `@orchestrate` | `.llma/agents/*.md`, `.claude/agents/*.md` | `.llma` выигрывает; если цепочки `.llma/agents/01-…` есть, чужие роли не подмешиваются |

- В `.claude/skills` читается только `SKILL.md`; вложения (скрипты) агент не исполняет сам — только через `run_terminal` с подтверждением.
- Поле `tools` в `.claude/agents/*.md` ограничивает инструменты роли: имена вне белого списка отбрасываются, `tools: []` — запрет всех инструментов.
- Симлинки и файлы больше 256 КБ пропускаются; каталог скилов в промпте ограничен 6 000 знаками.
- Проверить, что реально попало в промпт: команда **`LLM Assistant: Показать источники правил`** (отчёт без содержимого и абсолютных путей).

## Роли (`agents/`)

Имя файла = имя роли. `reviewer.md` используется командой `LLM Assistant: Review File`, роли из `agents/` доступны через `@orchestrate` и делегирование.

Если `.llma/agents/` пуст или отсутствует, плагин берёт три встроенные роли: `architect`, `coder`, `reviewer` (короткие промпты «спроектируй / напиши / проверь»).

## Скилы (`skills/`)

Frontmatter обязателен, ключи: `name`, `version`, `description`, `tools`.

```markdown
---
name: my-skill
version: 1.0.0
tools: [read_file, search_files]
description: Проверяет changelog на пропущенные релизы
---

# Скил: Мой скил

## Описание
Одно-два предложения о назначении.

## Задача
Какие типы задач решает.

## Правила
- Конкретные инструкции

## Запрещено
- Что нельзя делать
```

Как это работает:

1. Плагин сканирует `.llma/skills/` и добавляет в промпт агента таблицу «имя → `description`».
2. В промпте стоит правило: если задача соответствует скилу — **сначала** `read_file(.llma/skills/<имя>.md)`, и только потом работа.
3. Поэтому `description` — не украшение: по нему модель решает, читать скил или нет. Пустое описание = скил не выберется.
4. Вызов вручную: `/my-skill` (по имени файла) или `/skill my-skill`. Содержимое файла подставляется в начало диалога.

## Планы (`plans/`)

План-режим создаёт `.llma/plans/plan_<YYYY-MM-DD>_<id>.md` со структурой:

```
## 📦 Затронутые компоненты
## 🔧 Этапы реализации
## ✅ Контрольные точки (AC)
## 🔍 Инструкция для ревьюеру
## ⚠️ Риски
## 📝 История
```

Раздел AC — то, по чему потом проверяется реализация: ревьюер плана и финальный прогон опираются на него, а не на текст этапов. Папку `.llma/plans/` плагин создаёт сам при первом плане.

## Лимиты

| Что | Значение | Откуда |
|-----|----------|--------|
| Шагов агента в чате | `llmAssistant.agent.maxIterations` = 15 | настройка |
| Шагов apply-режима | `llmAssistant.apply.maxIterations` = 20 | настройка |
| Отказов в подтверждении подряд | 2 → прогон останавливается | `MAX_DENIALS` в `AgentWorker` |
| Контекст истории чата | `llmAssistant.chat.maxContextTokens` = 0 (авто по окну модели; число — жёсткий потолок) | настройка |
| Порог summary при переполнении | `llmAssistant.chat.summaryTriggerTokens` = 2048 | настройка |
| Окно контекста локальной модели | `llmAssistant.local.numCtx` = 8192 | настройка, отдельно от истории чата |
| Токенов под промпт при локальном движке | ≈ `numCtx / 2` (512→258, 4096→2050, 16384→8194 — замер 09.11) | Ollama резервирует половину окна под ответ; плагин предупреждает, когда счётчик дошёл до этой границы |

## Частые ошибки

| Симптом | Причина |
|---------|---------|
| Скил не выбирается сам | пустой `description` во frontmatter |
| Роль отвечает «не своим» промптом | нет файла `.llma/agents/<роль>.md`, сработал `main.md` или дефолтная роль |
| Правила не применились | `.llma` лежит не в корне workspace, или `agentsMd.enabled = false` для `AGENTS.md` |
| План не сохранился | нет прав на запись в workspace; папка `.llma/plans/` создаётся автоматически |
