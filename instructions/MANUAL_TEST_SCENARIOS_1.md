## 1. ask_user — уточняющие вопросы агента ⚡ NEW

**Сборка:** F5 или `npm run compile`  
**Версия VSIX:** последняя (0.8.3+)

### 1.1 QuickPick с вариантами

1. Открой чат, переключись в режим 🤖 Агент
2. Напиши: «Помоги выбрать название для функции, которая считает сумму массива. Спроси у меня варианты.»
3. **Ожидание:** агент вызывает `ask_user` с `options` — появляется QuickPick с твоими вариантами (должен предложить несколько названий)
4. Выбери вариант → агент продолжает, используя твой выбор
5. **✅ AC-1.1:** QuickPick с вариантами, возвращает выбранный

### 1.2 QuickPick — Escape / закрытие

1. Спроси агента что-то, что требует выбора (чтобы он вызвал `ask_user` с options)
2. Когда появится QuickPick — нажми Escape
3. **Ожидание:** агент получает `(пропущено)` и продолжает без выбора
4. **✅ AC-1.3:** Закрытие возвращает «(пропущено)»

### 1.3 InputBox (без вариантов)

1. Напиши: «Спроси у меня, какой порог использовать для фильтрации.»
2. **Ожидание:** появляется InputBox с плейсхолдером «Ваш ответ...»
3. Введи значение (например, `0.75`) → Enter
4. Агент использует введённое значение
5. **✅ AC-1.2:** InputBox с открытым вводом

### 1.4 2 варианта → кнопки Да/Нет

1. Напиши: «Спроси, нужно ли добавить обработку ошибок.»
2. **Ожидание:** `showInformationMessage` с кнопками (2 варианта → да/нет)
3. Нажми одну из кнопок
4. **✅ AC-1.5:** 2 опции → информационное сообщение с кнопками

### 1.5 Пустой вопрос

1. Напиши агенту задачу, которая НЕ требует уточнений: «Прочитай README.md»
2. **Ожидание:** агент НЕ вызывает `ask_user` без необходимости
3. **✅** Инструмент не вызывается зря

## 2. web_fetch — чтение веб-страниц ⚡ NEW (v0.8.3)

### 2.1 Чтение простой HTML-страницы

1. Режим 🤖 Агент
2. Напиши: «Прочитай страницу https://example.com и скажи, о чём она.»
3. **Ожидание:** агент вызывает `web_fetch`, получает текст (до 15000 символов), анализирует
4. **✅ WF-1:** HTML→текст, удалены скрипты/стили/навигация

### 2.2 Не-HTML страница (JSON/текст)

1. «Прочитай https://api.github.com и скажи, какие эндпоинты доступны.»
2. **Ожидание:** возвращает сырой текст (без HTML-обработки), обрезанный до 15000
3. **✅** Content-Type не html → сырой текст

### 2.3 CSS-селектор

1. «Из статьи https://habr.com/ru/articles/... достань только основной текст (селектор `.article__body`).»
2. **Ожидание:** агент передаёт `selector` в `web_fetch`; текст только из указанного блока
3. **✅ WF-2:** Селектор работает

### 2.4 Ошибка HTTP

1. «Прочитай https://httpstat.us/404»
2. **Ожидание:** `HTTP 404: Not Found`
3. **✅** Корректная обработка HTTP-ошибок

### 2.5 Таймаут / недоступный URL

1. «Прочитай https://10.255.255.1/» (недоступный IP)
2. **Ожидание:** ошибка с сообщением (не зависает)
3. **✅** Таймаут 15 сек работает

## 3. Индикатор токенов в шапке чата (v0.8.2)

### 3.1 Появление при отправке

1. Отправь любое сообщение в чат (режим 💬 Чат)
2. **Ожидание:** в шапке чата появляется индикатор: `📊 Токены: IN+OUT | 💰 $X.XXXXXX` + прогресс-бар
3. **✅** Индикатор отображается после каждого запроса

### 3.2 Сброс при смене сессии

1. Сделай несколько запросов (индикатор должен быть виден)
2. Создай новую сессию (кнопка «+»)
3. **Ожидание:** индикатор сброшен (пустой/скрыт)
4. **✅** Сброс при новой сессии

### 3.3 Корректность данных

1. Отправь длинный запрос → IN-токенов должно быть больше
2. Попроси короткий ответ («Ответь одним словом») → OUT-токенов мало
3. **Ожидание:** числа пропорциональны реальным размерам
4. **✅** Данные коррелируют с реальностью

## 4. delegate_to_agent — делегирование (MA-6, v0.8.1)

**Подготовка:** создай файл `.llma/agents/tester.md` с содержимым:
```markdown
# Tester
Ты — тестировщик. Пиши unit-тесты и проверяй код на ошибки.
```

### 4.1 Делегирование в чат-агенте

1. Режим 🤖 Агент
2. Напиши: «Прочитай src/modes/chat/AskUserTool.ts, делегируй тестировщику задачу "напиши тесты для этого файла".»
3. **Ожидание:** агент читает файл, затем вызывает `delegate_to_agent(role='tester', task='...')`. Появляется ответ от тестировщика.
4. **✅ MA-6:** delegate_to_agent работает в чат-агенте

### 4.2 Роль не найдена

1. «Делегируй задачу агенту `nonexistent` — "проверь код".»
2. **Ожидание:** агент пытается делегировать, получает ошибку или синтетический ответ
3. **✅** Graceful degradation для неизвестной роли

### 4.3 Делегирование в @orchestrate

1. В чате напиши: `@orchestrate Проверь безопасность обработки входных данных в API-эндпоинтах.`
2. **Ожидание:** оркестратор запускает цепочку агентов, один из которых может вызвать `delegate_to_agent` для узкой подзадачи
3. **✅** Делегирование работает внутри оркестрации

## 5. Cost tracking (MA-7, v0.8.1)

### 5.1 Стоимость в истории запусков

1. Сделай несколько запросов в 🤖 Агенте
2. Открой вкладку «📊 История»
3. **Ожидание:** каждая запись содержит:
   - Токены (вход + выход)
   - Стоимость `$X.XXXXXX`
   - Продолжительность
4. **✅ MA-7:** Стоимость записывается в историю

### 5.2 Стоимость оркестрации

1. Выполни `@orchestrate простая задача`
2. После завершения:
   - В чате: итоговая строка с токенами и стоимостью
   - Во вкладке «📊 История»: запись с общей стоимостью
3. **✅** Cost tracking для оркестратора

### 5.3 Сводка стоимости в чате

1. `@orchestrate Напиши функцию, которая реверсирует строку.`
2. **Ожидание:** в конце вывода:
   ```
   🎭 **Оркестрация завершена.** Токенов: XXX+YYY | Стоимость: $0.XXXXXX
   ```
3. **✅** Сводка стоимости в чате

## 6. @orchestrate — мульти-агентная оркестрация (v0.8.0)

**Подготовка:** `.llma/agents/` с файлами:
```
01-architect.md   (архитектор)
02-coder.md       (разработчик)
03-reviewer.md    (рецензент)
tester.md         (тестировщик, без префикса → только delegate)
```

### 6.1 Запуск оркестрации

1. В 🤖 Агенте напиши: `@orchestrate Создай функцию для валидации email-адресов.`
2. **Ожидание:**
   - Открывается вкладка «🎭 Оркестратор»
   - Появляются воркеры (architect → coder → reviewer)
   - Статусы меняются: pending → running → done/error
   - Результаты каждого воркера в чате
3. **✅ MA-2:** Оркестратор создаёт и запускает воркеров

### 6.2 Цепочка (sequential)

1. `@orchestrate Спроектируй и реализуй класс UserService.`
2. **Ожидание:**
   - Архитектор проектирует → результат передаётся кодеру → код передаётся рецензенту
   - Каждый видит результат предыдущего
3. **✅ MA-2.3:** Контекст передаётся между воркерами

### 6.3 MCP-инструменты в оркестраторе

1. Настрой MCP-сервер в `.vscode/mcp.json`
2. `@orchestrate Используй git для анализа изменений.`
3. **Ожидание:** оркестратор передаёт MCP-инструменты воркерам, они используют git
4. **✅ MA-2.6:** extraTools передаются воркерам

### 6.4 Ошибка воркера

1. `@orchestrate Напиши код, который гарантированно упадёт (используй несуществующий API).`
2. **Ожидание:**
   - Кодер падает с ошибкой
   - Цепочка прерывается
   - Ошибка отображается в чате и вкладке оркестратора
3. **✅ MA-2.5:** Ошибка обрабатывается

### 6.5 Результаты в истории

1. После оркестрации открой «📊 История»
2. **Ожидание:** запись с mode='orchestrator', суммированными токенами и стоимостью
3. **✅** История записывается корректно

## 7. ReAct-агент + реальные токены (v0.8.0)

### 7.1 Агентный режим с инструментами

1. 🤖 Агент: «Создай файл test-manual.md в корне проекта и запиши туда список моих любимых языков: TypeScript, Python, Rust.»
2. **Ожидание:** агент:
   - Вызывает `write_file` с `test-manual.md`
   - Появляется диалог подтверждения — нажми «✅ Подтвердить»
   - Файл создаётся
3. **✅** ReAct-цикл + подтверждение операций

### 7.2 Подтверждение — отказ

1. «Перезапиши README.md пустым файлом.»
2. В диалоге подтверждения нажми «❌ Отмена»
3. **Ожидание:** агент получает отказ, файл не трогается
4. **✅** Отказ обрабатывается

### 7.3 Лимит итераций

1. Дай агенту задачу, которую нельзя решить имеющимися инструментами: «Найди все TODO в проекте, отсортируй по приоритету и создай задачи в Jira.»
2. **Ожидание:** агент пробует 5 итераций, потом сообщает «Агент не дал финального ответа»
3. **✅** Лимит итераций (5 для чата)

### 7.4 Неагентный режим (💬 Чат)

1. Переключись на 💬 Чат
2. «Привет, как дела?»
3. **Ожидание:** отвечает без вызова инструментов (нет ReAct-цикла)
4. **✅** Чат без инструментов

### Найденные и исправленные баги

1. **Системный промпт** — перечислял только 5 инструментов, ask_user/web_fetch/delegate не упоминались → модель не вызывала (0.8.4–0.8.5)
2. **`\b` не работает с кириллицей** — все триггеры ask_user молчали → заменено на `(?:^|\s)` (0.8.12)
3. **`[object Object]` в модели** — WebView не извлекал `.name` из объектов `{name, pricing}` → фикс в main.js (0.8.19)
4. **InputBox после модалки** — коллизия двух UI-вызовов → убрана промежуточная модалка (0.8.7)
5. **Авто-Да/Нет** — добавлено в сам инструмент, модель не обязана передавать options (0.8.12)
