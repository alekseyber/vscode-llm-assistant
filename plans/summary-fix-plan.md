# План исправления: Summary в чате и агенте (Шаги 2.1, 2.2)

**Дата:** 05.08.2026
**Задача:** Починить накопление истории чата и добавить summary для агента

---

## Шаг 2.1 — Длинный диалог (история не накапливается)

### Симптомы
- Каждый запрос видит только 1 сообщение (`historyMsgs=1`), даже после 5+ сообщений
- `trimmed=0` → summary никогда не запускается
- В логах: `trimmed=0` при любом количестве сообщений

### Диагностика (в 19:00)
1. Проверить `ConversationManager.addMessage()` — сохраняются ли сообщения в storage
2. Проверить `ConversationManager.getMessagesForRequest()` — возвращает ли все сообщения
3. Проверить `ConversationManager.getMessagesForHistory()` — используется ли правильный метод
4. Выяснить, не очищается ли история при каком-то событии (restoreHistory, переключение сессии)

### План исправления
**Вариант А:** `getMessagesForRequest` некорректно обрезает историю из-за `maxContextTokens=512`
  - Поднять до 4096 для проверки
  - Если помогает — баг в обрезке токенов (слишком агрессивная)

**Вариант Б:** `addMessage` не сохраняет в storage (globalState/workspaceState)
  - Проверить `storage.update()` вызывается после каждого сообщения
  - Добавить логирование количества сообщений в storage

**Вариант В:** Сессия пересоздаётся при каждом запросе
  - Проверить `restoreHistory`/`getActiveSession`
  - Убедиться что `addMessage` добавляет в ту же сессию

### Acceptance Criteria
- [ ] После 5+ сообщений `historyMsgs >= 5`
- [ ] `trimmed > 0` при `maxContextTokens=512`
- [ ] `willSummarize=true` при `trimmedTokens >= 256`
- [ ] System prompt содержит `## Краткое содержание предыдущего диалога`

## Шаг 2.2 — Summary в агенте

### Симптомы
- Агент не использует summary для длинных цепочек шагов
- При >5 шагов агента сообщения не сжимаются
- Неясно, применяется ли `ConversationManager` к агенту

### Диагностика (в 19:00)
1. Проверить, как `runAgentLoop` управляет сообщениями (свой массив `messages` или через `ConversationManager`)
2. Проверить, сохраняются ли шаги агента в `ConversationManager`
3. Проверить, нужно ли внедрять summary между итерациями агента

### План исправления
**Вариант А:** Инжект summary между итерациями агента
  - После каждого ответа агента проверять `getMessagesForRequest`
  - Если есть summary — вставлять как system-сообщение в массив `messages`

**Вариант Б:** Сохранение шагов агента в ConversationManager
  - После каждого tool_call сохранять в CM
  - `getMessagesForRequest` возьмёт на себя summary

### Acceptance Criteria
- [ ] При 5+ итераций агента в логах появляется summary
- [ ] Summary вставляется как system-сообщение в массив messages агента
- [ ] Не ломает существующую логику агента (инструменты, подтверждения)
